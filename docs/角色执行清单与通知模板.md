# 角色执行清单与通知模板（含 UI / 安全 / 性能 / 功能完成度扫描）

> 用途：把“必须做的事”变成各角色可执行的检查清单，并提供可直接转发给对应负责人的通知文案。  
> 适用：Porcelain ERP（Electron + Web），配合《AI 协作规则树 v3.2》。

---

## 1. 版本发布的硬门槛（Gates）

每次发布（或提测）至少满足：

1) **功能正确性**：QA 按 PRD 验收标准通过  
2) **UI/交互质量**：线上测试工程师（发布验证）通过（含弹窗遮挡、布局、动效、点击可用性）  
3) **安全基线**：安全检查通过（Electron 安全项 + 依赖风险 + IPC/数据安全）  
4) **性能基线**：性能检查通过（启动、页面交互、动画流畅度、包体/资源、内存/CPU）  
5) **功能完成度盘点**：自动扫描报告已更新（明确哪些按钮/功能未实现或故障）

> 说明：QA 通过 ≠ 发布通过；DevOps 构建通过 ≠ 发布通过。

---

## 2. 各角色“必须做”清单（可直接复制到 dev-tasks / PR）

### 2.1 PM（产品经理）
- [ ] PRD 中明确：关键路径 + 异常流程 + 边界条件 + 可量化验收标准
- [ ] 标注哪些页面/弹窗属于“发布必测 UI 清单”
- [ ] 对安全/性能提出最低验收指标（如：启动时间、关键操作响应、敏感数据处理要求）
- [ ] 基于功能完成度盘点（feature-inventory）规划版本（version-plan）

### 2.2 UX 设计师
- [ ] 输出关键页面的 7 态规范（loading/empty/error/disabled/hover/focus/success）
- [ ] 明确弹窗/抽屉/下拉的交互规则（遮罩、关闭方式、滚动策略、层级）
- [ ] 动效参数清单：时长、缓动、触发条件、降级策略（低性能设备/窗口缩放）

### 2.3 架构师
- [ ] Electron 安全基线：contextIsolation/nodeIntegration/sandbox 策略；IPC 白名单与参数校验
- [ ] 数据安全：敏感字段与脱敏策略、日志不泄露、token/本地存储加密策略
- [ ] 性能设计：渲染进程分包/懒加载策略、长列表/图表性能策略、DB 查询索引/分页策略

### 2.4 开发者
- [ ] 完成验证链：prettier → eslint → tsc → 测试（按规则）
- [ ] UI/交互自测：按“发布必测 UI 清单”至少走一遍关键路径
- [ ] 安全自检：不新增敏感信息硬编码；IPC 调用走统一封装；不把底层错误直接透传 UI
- [ ] 性能自检：避免主线程阻塞（大计算/大渲染）；动画避免频繁布局抖动（layout thrash）
- [ ] 为关键页面/按钮补齐 `data-testid` / `data-action`（支撑自动扫描）

### 2.5 审查员（Code Reviewer）
- [ ] UI 风险审查：弹窗/下拉是否使用 portal；是否存在 overflow 裁剪风险；z-index 是否合理
- [ ] 安全审查：Electron 安全项、IPC 白名单、输入校验、敏感字段/日志、依赖风险（含审查结论）
- [ ] 性能审查：大组件是否拆分/懒加载；是否引入重依赖；渲染进程产物体积是否异常增长

### 2.6 QA（测试工程师）
- [ ] 基于 PRD 验收标准：功能测试 + 边界测试 + E2E（如有）
- [ ] 安全测试（基础）：常见越权/权限不足、错误信息泄露、输入异常（超长/特殊字符）等
- [ ] 性能测试（基础）：关键路径响应时间、长列表/图表交互卡顿、异常网络下体验
- [ ] 协同自动扫描：为关键页面/按钮补齐 `data-testid`，提升“按钮完成度扫描”稳定性

### 2.7 DevOps
- [ ] 构建/打包通过并可访问（安装包/链接/版本号/构建信息）
- [ ] 产物体积与启动日志基线记录（便于回归对比）
- [ ] 安全与性能检查命令在 CI/发布脚本中可一键执行（至少保证发布前有人能跑）
- [ ] 自动扫描任务可一键运行并产出报告（feature-scan-report），发布前必须更新一次

### 2.8 线上测试工程师（Online QA）
- [ ] 在“发布产物/可访问环境”执行：UI 冒烟清单（布局/遮挡/可点击/动效）
- [ ] 必须取证：复现步骤 + 截图/录屏 + Console/Network/日志摘要 + 严重度
- [ ] 对每轮修复做回归，并更新发布验证报告，直到通过或阻塞
- [ ] 对“扫描发现的未实现/故障入口”做抽样人工复核（避免误报），并回写状态

## 3. 通知模板（复制给对应负责人即可）

### 3.1 给 PM
本版本开始，发布前必须满足 5 个门槛：功能（QA）+ UI/交互（线上测试）+ 安全 + 性能 + 功能完成度盘点（自动扫描报告）。请在 PRD 中补齐：关键路径/异常/边界/可量化验收标准，并标注“发布必测 UI 清单”和最低安全/性能指标；并基于 feature-inventory 规划 version-plan。

### 3.2 给 UX
请输出：关键页面 7 态规范、弹窗/抽屉/下拉规则（遮罩/滚动/关闭/层级）、动效参数清单（时长/缓动/触发/降级）。这些将作为线上测试工程师的发布验证口径。

### 3.3 给架构师
请补齐并固化：Electron 安全基线（contextIsolation/nodeIntegration/sandbox + IPC 白名单/参数校验）、数据安全策略（敏感字段/日志不泄露/本地加密），以及性能设计（分包/懒加载/长列表/DB 查询策略）。发布前需要给出“安全/性能检查清单与命令”。

### 3.4 给开发者
除验证链外，本版本开始必须做：UI 自测（发布必测 UI 清单至少走一遍）+ 安全自检（不透传底层错误、不泄露敏感字段、IPC 统一封装与校验）+ 性能自检（避免主线程阻塞，关注大列表/图表/动画流畅度）。同时为关键页面/按钮补齐 `data-testid/data-action`，确保自动完成度扫描可跑。

### 3.5 给审查员
审查范围除代码规范外，新增“安全与性能审查结论”：Electron 安全项、IPC 白名单、输入校验、敏感字段/日志、依赖风险；性能方面关注 bundle 体积变化、懒加载、重依赖与大组件渲染风险。需在审查报告中分级记录（Critical/Major/Minor）。

### 3.6 给 QA
请在原功能测试外补充：基础安全测试（越权/错误泄露/异常输入）与基础性能测试（关键路径响应、长列表/图表卡顿、弱网体验）。测试报告需新增“安全/性能”小节；并协同推动关键页面/按钮补齐 `data-testid`，让自动化完成度扫描可靠运行。

### 3.7 给 DevOps
请在发布记录中新增：产物体积/启动耗时等性能基线，以及安全/性能检查的可执行入口（CI 或发布脚本）。发布前必须一键跑出自动完成度扫描报告（未实现/故障入口清单），并在发布后进入线上测试工程师验证环节，未通过不得进入用户验收。

### 3.8 给线上测试工程师
发布后必须在真实产物/可访问环境执行 UI/交互冒烟与回归：布局/遮挡/可点击/动效。所有问题必须带取证（步骤+截图/录屏+日志摘要+严重度），并推动修复闭环；同时对自动扫描标记的未实现/故障入口做抽样人工复核并回写状态。
