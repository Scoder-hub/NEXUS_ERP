## 3. 发现的问题

### 🟡 Bug-004: 无变更时保存仍创建版本（违反 BR-V03）

| 项目 | 内容 |
|------|------|
| PRD 规则 | BR-V03: **保存时无变更（isDirty=false），不创建新版本，提示"无变更无需保存"** |
| 实际行为 | 点击"保存"/Ctrl+S 直接打开保存对话框，输入说明即可保存，不检查 `isDirty` |
| 影响 | 连续点 2 次保存会创建 2 个空版本（内容相同），产生无意义的历史条目 |
| 建议修复 | `handleSave` 中检查 `editor.isDirty`，若 false 则提示"无变更无需保存"不弹对话框 |
| 严重度 | 🟡 Major |

### 🟡 Bug-005: 发布时不检查 isDirty，可能导致状态丢失

| 项目 | 内容 |
|------|------|
| 实际行为 | `publishRoute()` 先调 `saveRoute()` 再 `ROUTE_PUBLISH`。`saveRoute()` 没有对话框，直接存档+保存 |
| 问题 | 如果用户在进入编辑器后从未保存，直接点"发布"，`saveRoute()` 存档当前 v0.1 空快照，发布状态且 v1.0。编辑器中的节点会丢失 |
| 场景 | 创建新路线 → 拖入节点 → 不先保存 → 直接点"发布" |
| 建议修复 | 发布前检查 isDirty 且未保存过，先弹 SaveConfirmDialog 要求填写变更说明 |
| 严重度 | 🟡 Major |

### 🟢 Bug-006: 发布按钮在已发布路线仍可见（UI 逻辑）

| 项目 | 内容 |
|------|------|
| 实际行为 | `index.tsx:189`: `{cur?.status === "draft" && (<button ...>发布</button>)}` — 仅 draft 显示 |
| 结果 | ✅ 正常 — draft 才显示发布按钮 |
| 备注 | ❌ **误报** — 代码正确，撤回此发现 |

### 🔵 优化建议: 版本号上限未检测

| 项目 | 内容 |
|------|------|
| 边界条件 PRD | 版本号达到 v999.999 时提示"版本号已达上限" |
| 实际 | handlers.ts 中 `parseInt(ver[0]) || 0` 和 `parseInt(ver[1]) || 0` 没有上限检查 |
| 建议 | 在 ROUTE_SAVE 和 ROUTE_PUBLISH 中增加版本号上限检查 |
| 严重度 | 🔵 优化 |

### 🔵 优化建议: 删除路线未清理版本历史

| 项目 | 内容 |
|------|------|
| 实际 | `ROUTE_DELETE` handler 仅删除 routes 表，不删除关联的 route_history |
| 影响 | 长期使用后 route_history 表可能有孤立数据 |
| 建议 | 删除路线时同步删除 route_history 关联记录 |
| 严重度 | 🔵 优化 |
