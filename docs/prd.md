## 一、项目概述

### 1.1 项目背景

NEXUS ERP 是一套面向陶瓷制造企业的全流程资源管理系统。当前项目处于原型阶段，已有一个基于 React 19 + TypeScript 的前端原型，包含 20 个页面和 11 个自定义组件，所有数据均为硬编码 mock 数据。系统尚未接入后端、数据库和真实状态管理，不具备业务处理能力。

本项目的目标是将原型转化为可投入生产使用的桌面端 Electron 应用，实现从采购、生产、销售、库存到财务、人事的全链路数字化管理。

### 1.2 目标用户

| 用户角色 | 职责描述 | 核心诉求 |
|---|---|---|
| 系统管理员 | 系统配置、用户管理、数据备份、权限分配 | 完整的系统控制能力、数据安全保障 |
| 采购主管 | 采购订单管理、供应商管理、采购审批 | 采购流程透明、供应商评估可量化 |
| 销售经理 | 销售订单管理、客户管理、销售报表 | 订单跟踪实时、客户分级管理 |
| 生产总监 | 生产计划排程、车间执行监控、工单管理 | 生产进度可视化、异常及时预警 |
| 车间操作员 | 工位操作、生产报工、工艺卡执行 | 报工便捷、工序指引清晰 |
| 财务主管 | 财务数据管理、收付款记录、预算控制 | 收支清晰、审批流程规范 |
| HR 主管 | 员工信息管理、薪资管理、考勤管理 | 人事数据准确、流程合规 |
| 仓库管理员 | 库存管理、出入库操作、库存盘点 | 库存实时准确、预警及时 |

### 1.3 核心价值

1. **全流程数字化**：覆盖陶瓷企业从原料采购到成品出库的完整业务链
2. **生产过程透明化**：实时监控车间工位状态、工序进度、设备运行情况
3. **数据驱动决策**：多维度报表和可视化看板支撑管理决策
4. **本地化部署**：Electron + SQLite 架构，数据全部本地存储，无需云服务，保障数据安全与隐私
5. **多语言支持**：内置 6 种语言基础设施，支持国际化扩展

### 1.4 技术架构概要

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 桌面框架 | Electron | 主进程 + 渲染进程，contextIsolation=true |
| 前端框架 | React 19 + TypeScript | 保持现有技术栈 |
| UI 框架 | Tailwind CSS 4 + shadcn/ui + Radix UI | 保持现有设计系统 |
| 图表库 | Recharts | 保持现有选型 |
| 状态管理 | Zustand（需引入） | 轻量级，适合桌面应用 |
| 数据库 | better-sqlite3 | 同步 API，性能优异 |
| ORM | Drizzle ORM | 类型安全，与 TS 深度集成 |
| IPC 通信 | Electron ipcMain/ipcRenderer | 渲染进程 ↔ 主进程通信 |
| 表单验证 | Zod + react-hook-form | 已在依赖中 |

## 二、功能模块详细需求

### 模块 1：认证与权限（TASK-004）

#### 2.1.1 用户登录

- **功能描述**：用户通过用户名和密码登录系统，支持记住登录状态和锁屏功能
- **用户角色**：所有用户
- **业务规则**：
  - BR-001：用户名和密码为必填项，不可为空
  - BR-002：密码使用 bcrypt 哈希存储，禁止明文存储
  - BR-003：连续 5 次登录失败，账户锁定 30 分钟
  - BR-004：记住登录状态时，使用加密 token 存储在本地，有效期 7 天
  - BR-005：登录成功后记录登录时间和 IP 地址
  - BR-006：支持锁屏功能，锁屏后需输入 PIN 码或密码解锁
  - BR-007：会话超时自动锁屏（默认 30 分钟，可配置）
- **异常流程**：
  - AF-001：用户名不存在 → 提示"用户名或密码错误"（不泄露具体原因）
  - AF-002：账户被锁定 → 提示"账户已锁定，请 30 分钟后重试"
  - AF-003：数据库连接失败 → 提示"系统异常，请联系管理员"
- **边界条件**：
  - BC-001：密码长度 6-32 位，需包含字母和数字
  - BC-002：用户名长度 3-20 位，仅允许字母、数字、下划线
  - BC-003：同一账户同时在多设备登录时，可选策略：允许多设备 / 踢出前一个设备
- **可量化验收标准**：
  - AC-001：正确凭证登录响应时间 < 500ms
  - AC-002：错误凭证登录无系统信息泄露
  - AC-003：锁屏后无法通过任何快捷键绕过
  - AC-004：记住登录状态 7 天内免登录
- **优先级**：P0

#### 2.1.2 角色权限管理

- **功能描述**：基于角色的访问控制（RBAC），管理系统角色和权限分配
- **用户角色**：系统管理员
- **业务规则**：
  - BR-008：系统预置角色：超级管理员、管理员、部门主管、普通员工、访客
  - BR-009：权限粒度到页面级别 + 操作级别（查看/新增/编辑/删除/审批/导出）
  - BR-010：超级管理员不可删除、不可修改权限
  - BR-011：角色可自定义，每个角色可分配多个权限点
  - BR-012：用户可分配多个角色，权限取并集
- **异常流程**：
  - AF-004：删除正在使用的角色 → 提示"该角色下有 N 个用户，请先转移用户"
  - AF-005：权限不足访问页面 → 显示 403 提示，侧边栏隐藏无权限菜单
- **边界条件**：
  - BC-004：角色名称不可重复
  - BC-005：至少保留一个超级管理员账户
- **可量化验收标准**：
  - AC-005：权限变更后 1 秒内生效（无需重新登录）
  - AC-006：无权限页面完全不可见（侧边栏 + 路由双重控制）
  - AC-007：支持至少 50 个自定义角色
- **优先级**：P0

#### 2.1.3 个人资料管理

- **功能描述**：用户查看和编辑个人信息，修改密码，查看安全状态和近期动态
- **用户角色**：所有用户
- **业务规则**：
  - BR-013：用户可编辑姓名、手机号、个人简介
  - BR-014：邮箱、部门、职位、入职日期由管理员维护，用户不可修改
  - BR-015：修改密码需验证当前密码
  - BR-016：新密码不可与最近 3 次密码相同
  - BR-017：头像支持本地上传，存储在用户数据目录
- **异常流程**：
  - AF-006：当前密码验证失败 → 提示"当前密码不正确"
  - AF-007：新密码与旧密码相同 → 提示"新密码不可与旧密码相同"
- **边界条件**：
  - BC-006：头像文件大小 ≤ 2MB，支持 JPG/PNG
  - BC-007：个人简介 ≤ 200 字
- **可量化验收标准**：
  - AC-008：个人信息保存后即时生效
  - AC-009：密码修改后需重新登录
- **优先级**：P1

### 模块 2：仪表板（TASK-005）

#### 2.2.1 综合仪表板

- **功能描述**：展示企业核心 KPI 指标、收入趋势、近期订单、活动动态和系统状态
- **用户角色**：所有用户（数据按权限过滤）
- **业务规则**：
  - BR-018：KPI 卡片展示：本月营收、订单数、库存预警、生产达成率，数据从数据库实时计算
  - BR-019：收入折线图展示近 12 个月趋势，支持按月/季/年切换
  - BR-020：订单表格展示最近 10 条订单，支持点击跳转详情
  - BR-021：活动动态展示最近 20 条系统操作记录
  - BR-022：系统状态监控展示 CPU/内存/磁盘使用率
  - BR-023：数据按用户角色权限过滤，普通员工仅看本部门数据
- **异常流程**：
  - AF-008：数据库查询超时 → 显示缓存数据 + "数据可能不是最新"提示
  - AF-009：无数据时 → 显示空状态引导
- **边界条件**：
  - BC-008：首次使用无历史数据时，KPI 显示为 0
  - BC-009：活动动态最多保留 90 天
- **可量化验收标准**：
  - AC-010：仪表板加载时间 < 1 秒
  - AC-011：KPI 数据与数据库一致，误差率 0%
  - AC-012：图表交互响应时间 < 200ms
- **优先级**：P1

### 模块 3：采购管理（TASK-006）

#### 2.3.1 采购订单管理

- **功能描述**：创建、编辑、审批、跟踪采购订单的完整生命周期
- **用户角色**：采购主管（创建/编辑）、部门主管（审批）、仓库管理员（收货确认）
- **业务规则**：
  - BR-024：采购单号自动生成，格式：PO-YYYY-NNN（年-序号）
  - BR-025：采购单状态流转：草稿 → 待审批 → 已批准 → 采购中 → 运输中 → 已到货 → 已入库 → 已完成
  - BR-026：金额 ≥ ¥50,000 需二级审批（部门主管 + 财务主管）
  - BR-027：金额 ≥ ¥200,000 需三级审批（+ 总经理）
  - BR-028：已审批的采购单不可删除，仅可取消（需审批）
  - BR-029：到货确认后自动生成入库单（关联库存模块）
  - BR-030：支持按状态、供应商、日期范围筛选和搜索
- **异常流程**：
  - AF-010：审批人权限不足 → 提示"您无权审批此金额的采购单"
  - AF-011：供应商已停用 → 提示"该供应商已停用，请选择其他供应商"
  - AF-012：到货数量与采购数量不一致 → 允许部分到货，记录差异
- **边界条件**：
  - BC-010：单笔采购单商品明细 ≤ 100 行
  - BC-011：采购金额无上限，但超过 ¥500,000 需总经理审批
  - BC-012：草稿状态超过 30 天未提交自动归档
- **可量化验收标准**：
  - AC-013：采购单创建到提交审批 < 3 分钟
  - AC-014：审批操作响应时间 < 1 秒
  - AC-015：支持同时处理 ≥ 1000 条采购单不卡顿
- **优先级**：P0

#### 2.3.2 供应商管理

- **功能描述**：管理供应商信息、评估供应商绩效、维护供应商状态
- **用户角色**：采购主管
- **业务规则**：
  - BR-031：供应商信息包含：名称、类别、联系人、联系电话、地址、评级、状态
  - BR-032：供应商评级基于：交货准时率、质量合格率、价格竞争力、服务响应速度
  - BR-033：供应商状态：活跃、审核中、已停用
  - BR-034：停用供应商前需确认无进行中的采购单
  - BR-035：供应商评级每月自动计算更新
- **异常流程**：
  - AF-013：停用有进行中订单的供应商 → 提示"该供应商有 N 笔进行中订单，无法停用"
  - AF-014：供应商名称重复 → 提示"供应商名称已存在"
- **边界条件**：
  - BC-013：供应商评级 1.0-5.0，保留一位小数
  - BC-014：供应商数量无上限
- **可量化验收标准**：
  - AC-016：供应商列表加载时间 < 500ms
  - AC-017：评级计算准确率 100%
- **优先级**：P0

### 模块 4：销售管理（TASK-007）

#### 2.4.1 销售订单管理

- **功能描述**：创建、跟踪、管理销售订单，关联客户和产品信息
- **用户角色**：销售经理（创建/编辑）、部门主管（审批）
- **业务规则**：
  - BR-036：销售单号自动生成，格式：SO-YYYY-NNN
  - BR-037：销售单状态流转：草稿 → 待审批 → 已批准 → 处理中 → 已发货 → 已完成 / 已取消
  - BR-038：销售订单关联客户信息，自动填充客户地址和联系方式
  - BR-039：订单金额统计支持按月/季/年查看趋势
  - BR-040：支持按客户等级（钻石/白金/黄金/普通）分类管理
  - BR-041：发货后自动生成出库单（关联库存模块）
- **异常流程**：
  - AF-015：客户信用额度不足 → 提示"该客户应收账款已超信用额度"
  - AF-016：库存不足无法发货 → 提示"产品 XXX 库存不足，当前库存 N，需 M"
- **边界条件**：
  - BC-015：单笔销售单商品明细 ≤ 100 行
  - BC-016：客户信用额度可配置，默认 ¥0（不限制）
- **可量化验收标准**：
  - AC-018：月度销售图表数据与数据库一致
  - AC-019：TOP 客户排名实时更新
  - AC-020：订单搜索响应时间 < 300ms
- **优先级**：P0

#### 2.4.2 客户管理

- **功能描述**：管理客户信息、客户分级、客户交易历史
- **用户角色**：销售经理
- **业务规则**：
  - BR-042：客户信息包含：名称、等级、联系人、联系方式、地址、信用额度
  - BR-043：客户等级自动计算：基于年度交易金额和交易频次
  - BR-044：钻石：年交易额 ≥ ¥1,000,000；白金：≥ ¥500,000；黄金：≥ ¥100,000
  - BR-045：客户交易历史关联所有销售订单
- **异常流程**：
  - AF-017：删除有历史订单的客户 → 提示"该客户有 N 笔历史订单，无法删除，建议停用"
- **边界条件**：
  - BC-017：客户数量无上限
  - BC-018：客户等级每月重新计算
- **可量化验收标准**：
  - AC-021：客户等级计算准确率 100%
  - AC-022：客户搜索支持模糊匹配
- **优先级**：P0

### 模块 5：库存管理（TASK-008）

#### 2.5.1 产品库存管理

- **功能描述**：管理产品库存数量、库存预警、仓库管理、出入库记录
- **用户角色**：仓库管理员（日常操作）、采购主管/销售经理（查看）
- **业务规则**：
  - BR-046：库存信息包含：SKU、产品名称、库存数量、最低库存、单价、类别、仓库
  - BR-047：库存低于最低库存时自动触发预警通知
  - BR-048：出入库操作自动记录：类型（入库/出库）、数量、关联单号、操作人、时间
  - BR-049：仓库信息包含：名称、面积、已用比例、品类数
  - BR-050：仓库使用率 > 85% 显示预警
  - BR-051：支持库存盘点功能，生成盘点差异报告
- **异常流程**：
  - AF-018：出库数量 > 库存数量 → 提示"库存不足，当前库存 N"
  - AF-019：盘点差异 > 5% → 触发异常通知给部门主管
- **边界条件**：
  - BC-019：SKU 编码全局唯一
  - BC-020：库存数量 ≥ 0（不允许负库存）
  - BC-021：仓库数量 ≤ 20
- **可量化验收标准**：
  - AC-023：库存数据实时准确，与出入库记录一致
  - AC-024：库存预警在触发后 1 分钟内通知到相关人员
  - AC-025：出入库操作响应时间 < 500ms
- **优先级**：P0

### 模块 6：生产管理（TASK-009）

#### 2.6.1 生产计划排程

- **功能描述**：创建和管理生产工单，支持列表视图和甘特图视图，甘特图支持拖拽调整排程
- **用户角色**：生产总监（创建/排程）、车间操作员（查看）
- **业务规则**：
  - BR-052：工单号自动生成，格式：WO-YYYY-NNN
  - BR-053：工单信息包含：名称、产品型号、计划数量、单位、优先级、状态、起止日期、车间、进度
  - BR-054：工单状态：待生产 → 生产中 → 已完成
  - BR-055：优先级：高/中/低，高优先级工单在甘特图中突出显示
  - BR-056：甘特图支持拖拽调整工单起止日期
  - BR-057：工单排程冲突检测：同一车间同一时段不可重叠
  - BR-058：支持按状态筛选、按工单/产品搜索
- **异常流程**：
  - AF-020：排程冲突 → 提示"该时段已有工单 XXX，请调整时间"
  - AF-021：已完成工单不可修改排程 → 提示"已完成工单不可调整"
- **边界条件**：
  - BC-022：单日工单数 ≤ 50
  - BC-023：甘特图显示范围：当前月 ± 1 个月
  - BC-024：计划数量 > 0
- **可量化验收标准**：
  - AC-026：甘特图拖拽调整实时响应，延迟 < 100ms
  - AC-027：排程冲突检测准确率 100%
  - AC-028：支持同时展示 ≥ 30 条工单不卡顿
- **优先级**：P0

#### 2.6.2 车间执行管理

- **功能描述**：实时监控工位状态、工序流程追踪、生产报工
- **用户角色**：车间操作员（报工）、生产总监（监控）
- **业务规则**：
  - BR-059：工位信息包含：名称、类型、操作员、当前任务、状态、效率、温度、负载
  - BR-060：工位状态：运行中、空闲、维护中、异常
  - BR-061：工位数据每 5 秒刷新一次（模拟实时，实际为数据库轮询）
  - BR-062：工序流程追踪：展示工单的完整工序链，含工序名称、顺序、状态、时长、工位
  - BR-063：工序状态：待处理 → 进行中 → 已完成
  - BR-064：报工记录包含：工单号、工位、操作员、完成数量、不良品数、时间、备注
  - BR-065：报工后自动更新工单进度
  - BR-066：温度 > 80°C 或负载 > 90% 触发异常预警
- **异常流程**：
  - AF-022：报工数量 > 工单计划数量 → 提示"报工数量已超过计划数量"
  - AF-023：工位异常时自动通知生产总监
- **边界条件**：
  - BC-025：工位数量 ≤ 30
  - BC-026：单次报工完成数量 > 0
  - BC-027：不良品数 ≤ 完成数量

## 三、非功能需求

### 3.1 性能要求

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 应用启动时间 | 冷启动 < 3 秒，热启动 < 1 秒 | 从双击图标到登录页可见 |
| 页面切换时间 | < 300ms | 路由切换到内容渲染完成 |
| 数据库查询响应 | 简单查询 < 50ms，复杂查询 < 500ms | better-sqlite3 同步查询 |
| 内存占用 | 空闲状态 < 200MB，峰值 < 500MB | Electron 进程内存监控 |
| 数据库大小 | 支持 ≤ 10GB 数据库文件 | better-sqlite3 单文件限制 |
| 并发操作 | 单用户桌面应用，无并发要求 | N/A |

### 3.2 安全要求

| 要求 | 实现方式 |
|---|---|
| 密码存储 | bcrypt 哈希，salt rounds ≥ 10 |
| Electron 安全 | contextIsolation=true, nodeIntegration=false |
| SQL 注入防护 | Drizzle ORM 参数化查询，禁止 SQL 拼接 |
| XSS 防护 | React 默认转义 + CSP 策略 |
| 敏感信息 | 环境变量存储，禁止硬编码 |
| 数据加密 | SQLite 数据库文件可选加密（SQLCipher） |
| 操作审计 | 所有关键操作记录日志，日志不可篡改 |
| 会话安全 | Token 加密存储，自动过期，支持强制下线 |

### 3.3 可用性要求

| 要求 | 说明 |
|---|---|
| 深色/浅色主题 | 支持切换，默认深色，跟随系统偏好 |
| 响应式布局 | 最小支持 1280×720 分辨率 |
| 键盘操作 | 所有功能支持键盘操作，Tab 导航顺序合理 |
| 加载状态 | 所有异步操作显示加载指示器 |
| 错误提示 | 友好的错误提示，不暴露技术细节 |
| 数据验证 | 表单实时验证，错误提示明确 |
| 操作确认 | 危险操作（删除、恢复）需二次确认 |

### 3.4 可靠性要求

| 要求 | 说明 |
|---|---|
| 数据一致性 | 事务保证，操作失败自动回滚 |
| 自动备份 | 每日增量 + 每周全量，自动执行 |
| 崩溃恢复 | 应用崩溃后自动恢复到上次状态 |
| 数据迁移 | 版本升级时数据库自动迁移，支持回滚 |

### 3.5 兼容性要求

| 平台 | 版本 |

## 七、风险与约束

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| SQLite 单用户写锁 | 高并发写入性能受限 | 桌面应用单用户，影响可控；批量操作使用事务 |
| Electron 内存占用 | 长时间运行内存泄漏 | 定期内存监控，组件卸载时清理资源 |
| 数据库文件损坏 | 数据丢失 | 自动备份 + WAL 模式 + 定期完整性检查 |
| 原型代码质量 | 硬编码数据、无状态管理 | 逐步重构，优先接入数据库和状态管理 |
| 多语言翻译质量 | 翻译不准确影响体验 | 优先保证中英文质量，其他语言逐步完善 |
| 跨平台兼容性 | 不同 OS 表现差异 | 使用 Electron API 抽象平台差异，CI 多平台测试 |
