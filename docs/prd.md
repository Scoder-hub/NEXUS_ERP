## 1. 项目概述

### 1.1 项目背景

湖南兴诚电瓷电器有限公司是一家专注于电瓷绝缘子制造的实体企业，产品覆盖**制泥 → 成型 → 修坯 → 上釉 → 烧成 → 胶装 → 试验 → 包装** 8 道标准工序。当前公司生产管理主要依赖纸质工单和 Excel 表格，面临以下痛点：

| 痛点 | 影响 |
|------|------|
| 工艺路线依赖老师傅经验，未标准化 | 新人上手慢，工艺质量波动 |
| 工序流转纸质记录，易丢易漏 | 品质追溯困难 |
| 库存数据滞后 | 原材料断料/成品积压 |
| 质量检验结果分散登记 | 合格率分析靠人工统计 |
| 设备维护无预警 | 突发停机影响交期 |

### 1.2 项目目标

建设一套**桌面端优先、完全离线可用**的智能制造管理系统（IMS），实现：

1. **工艺标准化** — 工艺路线可视化设计、版本化管理
2. **生产过程数字化** — 工单流转、工序报工、批次追溯
3. **库存精细化** — 原材料/半成品/成品实时库存
4. **质量可追溯** — 来料→过程→成品全链路质检
5. **设备规范化** — 台账、保养、维修全生命周期管理

**一句话：让电瓷制造的每一道工序都有标准、有记录、可追溯。**

### 1.3 技术约束

| 约束项 | 说明 |
|--------|------|
| 架构 | Electron 30 + React 18 + TypeScript + Vite 6 |
| 数据库 | SQLite (better-sqlite3) — 本地优先，无需网络 |
| 画布 | React Flow（工艺路线设计器） |
| 部署 | 单机桌面应用，后续可扩展局域网协作 |
| 离线 | 完全离线运行，零网络依赖 |

### 4.2 生产管理（Production）

**目标**：实现工单全生命周期数字化管理，工序流转有记录、可追溯。

**这是 IMS 的核心模块**，覆盖从排产到成品入库的全过程。

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| P-01 | 生产工单管理 | 创建/编辑/关闭工单，关联工艺路线、订单、批号 | P0 |
| P-02 | 工单状态流转 | 待排产 → 生产中 → 已完成 → 已关闭 | P0 |
| P-03 | 工序报工 | 操作工扫码或手动选择工单，登记某工序完成数量、工时 | P0 |
| P-04 | 批次追溯 | 按批次号追溯该批产品每道工序的操作人、时间、参数 | P0 |
| P-05 | 在制品看板 | 当前每个工序的在制品数量，支持按产品/工单筛选 | P1 |
| P-06 | 排产甘特图 | 可视化排产，拖拽调整工单顺序 | P2 |
| P-07 | 产量统计报表 | 按日/周/月/产品统计产量（完工数、合格数、不合格数） | P1 |
| P-08 | 工序异常处理 | 工单在某工序标记异常（待料/设备故障/质量异常），暂停流转 | P1 |

**业务规则**：
- BR-P01: 工单必须关联一条**已发布**的工艺路线
- BR-P02: 工单流转路径由关联的工艺路线决定（跳过某些工序需特殊标记）
- BR-P03: 每道工序报工时必须记录：操作人、完成数量、工时、设备（如适用）
- BR-P04: 工序报工后自动更新在制品数量（上一工序减、下一工序加）
- BR-P05: 批次号生成规则：`YYYYMMDD-{产品代码}-{流水号}`（如 `20260711-P01-001`）
- BR-P06: 已完成工序不可回退报工（需管理员权限可撤销）

**验收标准摘要**：
- P-01：创建一个工单 ≤ 3 次点击
- P-03：工序报工 ≤ 10 秒/次（含数据录入）
- P-04：批次追溯响应 ≤ 2 秒
- P-07：月报导出 ≤ 3 秒

### 4.4 库存管理（Inventory）

**目标**：三类库存（原材料/半成品/成品）的全方位管理。

#### 4.4.1 原材料库存

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| I-01 | 原材料入库 | 采购到货登记：名称、规格、数量、批次号、供应商 | P0 |
| I-02 | 原材料出库 | 领料登记：关联工单、领用人、数量 | P0 |
| I-03 | 库存查询 | 按名称/规格/供应商/批次筛选，实时库存量 | P0 |
| I-04 | 库存预警 | 低于最低库存量时标红提醒 | P1 |
| I-05 | 盘点管理 | 新建盘点单、录入实盘数、生成盘盈盘亏记录 | P1 |

**原材料种类**：粘土、长石、石英、氧化铝、釉料、铁帽、水泥、包装材料等。

#### 4.4.2 半成品库存

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| I-06 | 半成品入仓 | 工序报工完成自动入半成品库（也可手动入仓） | P0 |
| I-07 | 半成品领用 | 下一工序领用出库，关联工单 | P0 |
| I-08 | 在库查询 | 按工序/产品/批次查询半成品库存 | P1 |

#### 4.4.3 成品库存

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| I-09 | 成品入库 | 包装工序完成 + 成品检验通过后自动入库 | P0 |
| I-10 | 成品出库 | 发货出库登记：关联客户/订单、数量、发货日期 | P0 |
| I-11 | 成品库存查询 | 按产品型号/批次/入库日期筛选 | P0 |
| I-12 | 库存报表 | 库存周转率、呆滞库存分析 | P2 |

**业务规则**：
- BR-I01: 原材料入库必须记录供应商和批次号（追溯用）
- BR-I02: 出库遵循**先进先出（FIFO）**原则，系统推荐最早批次
- BR-I03: 原材料最低库存量由系统管理员配置
- BR-I04: 半成品入仓/领用与生产工单绑定，不可独立操作
- BR-I05: 盘点期间涉及库存冻结，盘点完成后释放
- BR-I06: 所有出入库操作记录操作人、时间，不可删除（仅可红冲）

### 4.5 质量管理（Quality）

**目标**：建立来料→过程→成品的全链路质量管控体系。

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| Q-01 | 来料检验（IQC） | 原材料到货后检验：检验项目、标准值、实测值、判定 | P0 |
| Q-02 | 过程检验（IPQC） | 每道工序的质检记录，与工艺路线中的质检节点联动 | P0 |
| Q-03 | 成品检验（OQC） | 成品入库前最终检验：电气性能、机械性能、外观 | P0 |
| Q-04 | 不合格品管理 | 不合格品登记：缺陷类别、数量、处理方式（返工/报废/让步放行） | P0 |
| Q-05 | 检验标准配置 | 产品型号→检验项目→标准值/上下限 的模板配置 | P1 |
| Q-06 | 合格率统计报表 | 按产品/工序/时间统计一次合格率、不良品 Pareto 分析 | P1 |
| Q-07 | 质检记录追溯 | 按批次号查看该批所有质检记录 | P1 |
| Q-08 | 缺陷分类管理 | 自定义缺陷类别（如：尺寸超差、釉面缺陷、电气不合格） | P2 |

**业务规则**：
- BR-Q01: 质检判定结果三档：**合格 / 不合格 / 让步放行**
- BR-Q02: 不合格品必须记录处理方式（返工/报废），返工后重新检验
- BR-Q03: 过程检验结果实时回写到工单流转状态
- BR-Q04: 关键工序（烧成、试验）的质检结果必须录入系统才可流转下一工序
- BR-Q05: 检验标准可继承自工艺路线中质检节点的配置

**与工艺路线质检节点的联动**：
```
工艺路线中定义质检节点（检测项目+标准值）
        │
        ▼
工单流转到该质检节点时
        │
        ▼
质检员扫码/选择工单 → 系统自动加载检测项目列表
        │
        ▼
逐项录入实测值 → 系统自动判定合格/不合格
        │
        ▼
合格 → 继续流转下一工序
不合格 → 进入不合格品管理流程
```

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|

| E-03 | 保养记录 | 登记保养日期、保养人、保养内容、下次保养日期 | P1 |
| E-04 | 维修记录 | 故障报修→维修→验收：故障现象、原因、维修方案、费用 | P1 |
| E-05 | 设备状态 | 运行/停机/维修/保养 状态展示 | P1 |
| E-06 | 备件管理 | 备件库存、领用记录、最低库存预警 | P2 |

**主要设备类型**：

| 工序 | 主要设备 |
|------|---------|
| 制泥 | 球磨机、振动筛、除铁机、陈腐池 |
| 成型 | 旋坯机、注浆机、液压压机 |
| 修坯 | 修坯机、车床 |
| 上釉 | 浸釉机、喷釉柜 |
| 烧成 | 隧道窑、梭式窑 |
| 胶装 | 胶装台、养护室 |

**业务规则**：

- BR-E02: 保养到期提前 3 天在总览预警中心提醒
- BR-E03: 设备维修期间关联工单自动标记"设备异常"
- BR-E04: 关键设备（窑炉、球磨机）的保养记录不可删除

# TASK-006: 生产管理 — 工单管理 + 工序流转 PRD

> 版本: v1.0
> 角色: PM
> 日期: 2026-07-11
> 状态: 待审批

---

## 1. 概述

生产管理是兴诚电瓷 IMS 的**核心业务模块**，负责将「工艺路线」落地为实际生产执行。工单驱动产品在 8 道标准工序间流转，每道工序记录报工信息，实现从「原材料投入」到「成品产出」的全链路数字化。

**一句话：让每一张工单在工序间有序流转，每道工序都有记录、可追溯。**

### 与工艺路线关系

```
工艺路线定义 "怎么做"
        │
        ▼
工单引用路线，按路线节点逐工序流转
        │
        ▼
每到一个工序 → 操作工报工（数量、工时） → 质检（根据质检节点配置） → 流转下一工序
```

## 4. 工单状态流转

```
                    ┌──────────────┐
                    │  待排产       │  ← 新建工单默认状态
                    └──────┬───────┘
                           │ 排产确认（分配产线/班次）
                           ▼
                    ┌──────────────┐
                    │  生产中       │  ← 首道工序开始报工后自动进入
                    └──────┬───────┘
                           │
                 ┌─────────┼──────────┐
                 │         │          │
             ┌───▼──┐ ┌───▼──┐  ┌───▼──┐
             │工序1   │ │工序2 │  │工序N  │  ← 按工艺路线逐工序流转
             │报工    │→│报工   │→│报工   │
             └───┬───┘ └───┬───┘  └───┬───┘
                 │         │          │
                 └─────────┼──────────┘
                           │ 末道工序（包装）完成
                           ▼
                    ┌──────────────┐
                    │  已完成       │  ← 末道工序报工 + 成品检验通过
                    └──────┬───────┘
                           │ 关闭确认
                           ▼
                    ┌──────────────┐
                    │  已关闭       │  ← 不可再流转，仅查看
                    └──────────────┘
```

**异常分支**：

```
生产中 ──→ 暂停（待料/设备故障/质量异常）
暂停  ──→ 恢复生产（异常解除）
暂停  ──→ 终止（确认无法继续，报废处理）
```

## 5. 业务规则

### 5.1 工单规则

| ID | 规则 |
|----|------|
| BR-P01 | 工单必须关联一条**已发布**的工艺路线 |
| BR-P02 | 工单号自动生成，格式：`WO-{YYYYMMDD}-{3位流水号}` |
| BR-P03 | 同一工单不可同时关联两条不同工艺路线 |
| BR-P04 | 工单创建后「待排产」状态下可编辑产品/数量/路线；进入「生产」后不可编辑 |
| BR-P05 | 工单数量不得超过工艺路线中定义的产能上限（如有配置） |

### 5.2 工序流转规则

| ID | 规则 |
|----|------|
| BR-P06 | 工序流转顺序**严格按工艺路线定义的节点顺序**执行 |
| BR-P07 | **质检节点**：工单流转到质检节点时，必须先完成质检记录（合格/不合格），不合格品处理后才可继续流转 |
| BR-P08 | 每道工序报工时必须记录：**操作人、完成数量、工时**，可选记录：**设备、备注** |
| BR-P09 | 工序报工数量不可超过工单剩余数量（已报工累计 ≤ 工单总量） |
| BR-P10 | 报工数量可以分批（如 1000 件分 3 次报完），系统累计 |
| BR-P11 | 工序报工不可删除，仅可红冲（负数报工，需备注原因） |
| BR-P12 | 完成数量 = 合格数 + 不合格数，系统自动计算合格率 |
| BR-P13 | 工序回退时，被退回的工序重新变为「当前工序」，重新报工 |

### 5.3 状态变更规则

| ID | 规则 |
|----|------|
| BR-P14 | 首道工序首次报工 → 工单状态自动变为「生产中」 |
| BR-P15 | 末道工序报工完成 → 工单状态变为「已完成」 |
| BR-P16 | 状态变更时自动记录：变更时间、操作人、变更前状态、变更后状态 |
| BR-P17 | 「已完成」的工单不可再报工，「已关闭」的工单不可再操作 |

### 5.4 在制品规则

| ID | 规则 |
|----|------|
| BR-P18 | 某工序在制品数 = 上一工序报工完成的累计数量 − 本工序报工完成的累计数量 |
| BR-P19 | 首道工序在制品数 = 已投产数量 − 首道工序已报工数量 |
| BR-P20 | 末道工序无在制品（报工完成即进入成品库） |

## 6. 异常流程

| 场景 | 处理方式 |
|------|---------|
| 工单关联的工艺路线被归档 | 已流转中的工单不受影响，但无法引用该路线创建新工单 |
| 工序报工时数量超过工单剩余量 | 拒绝保存，提示"报工数量（含累计）不能超过工单总量 N" |
| 报工提交时网络/数据库写入失败 | 本地缓存该条报工记录，下次打开提示"有未提交的报工记录" |
| 某工序长时间未报工（超时） | 工单详情页标注黄色 ⏳ 超时提醒，由生产主管处理 |
| 工序回退时目标工序已被删除 | 回退到最近一个未被删除的工序 |
| 工单已全部报工但未标记完成 | 系统自动检测：末道工序报工累计 ≥ 工单总量 → 自动完成 |

## 7. 边界条件

| 条件 | 处理 |
|------|------|
| 工单数量为 0 或负数 | 创建时拒绝，提示"工单数量必须大于 0" |
| 工单列表为空 | 显示空状态引导："暂无工单，点击「+ 新建工单」开始生产" |
| 工序报工时数量为 0 | 警告"报工数量为 0 无法提交，请确认是否跳过此工序" |
| 同一天创建超过 999 个工单 | 提示"当日工单号已用尽，请次日创建"（实际概率极低） |
| 工单关联的路线无任何节点 | 创建时校验，提示"该工艺路线为空，无法创建工单" |
| 工艺路线包含质检节点但未配检测项目 | 流转到质检节点时提示"质检节点参数不完整，请工艺工程师处理" |
| 操作工一天报工超过 12 小时 | 提示"今日报工工时超过 12 小时，请确认" |

## 1. 概述

批次追溯和在制品看板是生产管理的**数据呈现模块**，建立在 TASK-006（工单管理 + 工序流转）的基础上。

- **批次追溯**：让用户按批次号追溯一批产品从投产到完工的全链路记录——每道工序谁做的、什么时候做的、参数是多少、质检结果如何。
- **在制品看板**：实时展示每个工序当前有多少产品正在加工，帮助生产主管掌握产线负荷、识别瓶颈工序。

**一句话：让每一批产品有迹可循，让每一道工序的产量一目了然。**

### 与 TASK-006 的关系

```
TASK-006 负责 "产生数据"
  ┌─ 工单创建
  ├─ 工序报工（产生报工记录）
  ├─ 状态变更（产生状态日志）
  └─ 质检判定（产生质检结果）

         │
         ▼

TASK-007 负责 "展示数据"
  ┌─ 批次追溯（按批次号聚合展示）
  ├─ 在制品看板（实时计算各工序在制数）
  └─ 产量统计（按产品/时间汇总）
```

## 6. 业务规则

### 6.1 批次追溯规则

| ID | 规则 |
|----|------|
| BR-T01 | 批次追溯数据**只读**，不可编辑、删除 |
| BR-T02 | 追溯路径由工艺路线节点顺序决定，而非报工时间顺序 |
| BR-T03 | 同一批次产品经过同一工序多次报工时，按时间顺序排列展示 |
| BR-T04 | 批次号全局唯一，不可重复 |
| BR-T05 | 追溯视图默认展示所有工序，支持按状态筛选（全部/正常/异常） |

### 6.2 在制品计算规则

| ID | 规则 |
|----|------|
| BR-T06 | 某工序在制品数 = ∑(上一工序报工合格数) − ∑(本工序报工合格数) |
| BR-T07 | 首道工序在制品数 = 工单计划数 − ∑(首道工序报工合格数) |
| BR-T08 | 末道工序在制品数恒为 0（报工完成即进入成品库） |
| BR-T09 | 在制品数量为 0 时显示 "-" 而非 0，避免误解 |
| BR-T10 | 在制品仅统计「合格数」，不合格品不计入在制品 |
| BR-T11 | 在制品看板默认按产品分组，支持按工单筛选 |

### 6.3 瓶颈阈值规则

| ID | 规则 |
|----|------|
| BR-T12 | 瓶颈阈值由系统管理员配置，每道工序独立设置（默认 300 件） |

## 7. 异常流程

| 场景 | 处理方式 |
|------|---------|
| 批次追溯查询的批次号不存在 | 提示"未找到该批次的生产记录" |
| 批次号对应的工单已删除 | 追溯视图只读展示已有记录，标记「工单已删除」 |
| 某工序报工记录被红冲 | 追溯视图中正常显示报工记录 + 红冲标记（删除线），实际数量以非红冲记录为准 |
| 在制品计算出现负数 | 标记为数据异常（🔴），提示管理员核查报工记录 |
| 查看追溯时对应 TASK-006 数据尚未同步 | 提示"数据加载中，请稍后" |
| 无任何在制品数据 | 显示"暂无在制品数据，请先创建工单并开始生产" |

# TASK-008 / TASK-009: 库存管理 PRD

> 版本: v1.0
> 角色: PM
> 日期: 2026-07-11
> 状态: 待审批

## 1. 概述

库存管理是兴诚电瓷 IMS 的**资源管理模块**，覆盖三类库存的全生命周期：**原材料**（采购入库→车间领用）、**半成品**（工序产出→下一工序领用）、**成品**（包装入库→发货出库）。

**一句话：让每一斤原料、每一件胚体、每一箱成品的进出都有记录、可追溯。**

### 三类库存关系

```
供应商 → 原材料入库                    客户 ← 成品出库
              │                              │
              ▼                              ▼
         ┌────────┐     ┌────────┐     ┌────────┐
         │ 原材料  │     │ 半成品  │     │ 成品   │
         │ 库存   │────▶│ 库存   │────▶│ 库存   │
         └────────┘     └────────┘     └────────┘
              │                              ▲
              ▼                              │
         车间领用                         生产完工入库
         (关联工单)                       (关联工单/质检)
```

## 5. 业务规则

### 5.1 通用库存规则

| ID | 规则 |
|----|------|
| BR-I01 | 全部出入库操作记录**操作人、时间、数量**，不可删除，仅可红冲（负数冲账+备注） |
| BR-I02 | 库存数量实时更新：入库 +，出库 −，不允许负库存（出库数量 > 库存量时拒绝） |
| BR-I03 | 出入库记录编号自动生成：`IN-{YYYYMMDD}-{3位流水}` / `OUT-{YYYYMMDD}-{3位流水}` |
| BR-I04 | 所有库存查询默认隐藏库存量为 0 的物料，可勾选「显示零库存」 |
| BR-I05 | 盘点期间相关物料冻结出入库操作，盘点完成后自动释放 |
| BR-I06 | 盘点差异率超过 5% 的物料自动标记🔴，需主管确认 |

### 5.2 原材料规则

| ID | 规则 |
|----|------|
| BR-I07 | 原材料入库必须记录**批次号**和**供应商**（追溯用） |
| BR-I08 | 原材料入库前必须完成来料检验（IQC），合格后才可入库 |
| BR-I09 | 出库遵循**先进先出（FIFO）**原则，系统自动推荐最早批次的库存 |
| BR-I10 | 同一原材料可有多批次库存，系统按批次分别记录，出库时优先出最早批次 |
| BR-I11 | 最低库存量由管理员配置，默认 0（不预警） |
| BR-I12 | 采购建议公式：建议量 = 近30天日均消耗 × 采购周期（天） − 当前库存 − 在途量 |

### 5.3 半成品规则

| ID | 规则 |
|----|------|
| BR-I13 | 半成品库存按「**工序 + 产品**」维度管理（不按独立物料编码），不同产品的半成品独立核算 |
| BR-I14 | 工序报工合格数 → 该工序半成品库存自动增加（或替换旧批次） |
| BR-I15 | 半成品领用出库时，按报工批次顺序先进先出 |
| BR-I16 | 半成品不独立设置预警阈值，由在制品看板的瓶颈预警覆盖 |
| BR-I17 | 半成品报废需关联工单（标记该批次中的不合格部分） |

### 5.4 成品规则

| ID | 规则 |
|----|------|
| BR-I18 | 成品入库前提是：包装工序完成 + 成品检验（OQC）合格 |
| BR-I19 | 成品按**产品型号 + 批次号**管理库存，不同批次分别核算 |
| BR-I20 | 成品出库时优先出最早批次（FIFO） |
| BR-I21 | 成品出库关联客户/订单信息，支持分批发货 |
| BR-I22 | 呆滞库存定义为：超过 90 天无出库记录的成品批次 |

## 7. 异常流程

| 场景 | 处理方式 |
|------|---------|
| 出库数量超过当前库存 | 拒绝操作，提示"库存不足，当前可用量：X" |
| 入库时选择不存在的原材料 | 提供"+ 新增原材料"快速入口，跳转到物料目录编辑 |
| 原材料未完成 IQC 检验试图入库 | 弹窗提示"该批次尚未完成来料检验，检验通过后方可入库" |
| 盘点期间有人试图操作被冻结的物料 | 提示"该物料正在盘点中，暂时锁定" |
| 成品出库时客户信息不完整 | 允许出库，但标记为"待完善客户信息" |
| 红冲操作填写的备注为空 | 拒绝保存，提示"红冲必须填写原因" |
| 系统日期变更导致批次号重复 | 拒绝创建，提示"当日批次号已用尽，请隔日操作"（实际概率极低） |

# TASK-002: 工艺路线设计器 — 基础阶段 PRD

> 版本: v1.0
> 角色: PM
> 日期: 2026-07-10
> 状态: 待审批

## 1. 概述

工艺路线设计器是电瓷智造 ERP 的核心模块，用于定义和管理电瓷产品的**制造工艺流程**。用户通过可视化的方式，将标准工序节点拖拽到画布上，连接成完整的工艺路线，并配置每个节点的执行参数。

**一句话：让工艺工程师像画流程图一样设计生产路线。**

---

## 2. 用户角色

| 角色 | 说明 | 使用频率 |
|------|------|---------|
| **工艺工程师** | 设计、编辑、维护工艺路线的主要用户 | 高频（每日） |
| **生产主管** | 查看和引用已发布的工艺路线 | 中频（每日） |
| **质检员** | 查看工艺路线上与本工序相关的参数 | 低频（按需） |
| **系统管理员** | 管理工序库、参数模板等基础数据 | 低频（按需） |

---

## 3. 功能需求

### 3.1 画布编辑器（核心）

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| F-01 | 从工序库拖拽工序节点到画布 | 左侧工序面板列出所有工序，用户拖拽到画布生成节点 | P0 |

# TASK-003: 工艺路线版本管理 PRD

> 版本: v1.0
> 角色: PM
> 日期: 2026-07-11
> 状态: 待审批

---

## 1. 概述

版本管理为工艺路线提供**完整的变更追踪能力**。每次保存路线时自动生成版本快照，用户可以查看历史版本、对比差异、回滚到任意历史版本。

**一句话：让每一次修改都有迹可循，随时可以回到任意历史状态。**

---

## 2. 用户角色

| 角色 | 说明 | 使用频率 |
|------|------|---------|
| **工艺工程师** | 设计路线时触发版本保存、查看历史、对比和回滚 | 高频（每次保存） |
| **生产主管** | 审查版本变更历史，确认路线变更内容 | 中频（按需） |
| **质量审核员** | 追溯特定版本的参数配置，确认合规性 | 低频（按需） |

---

## 3. 功能需求

### 3.1 版本历史记录

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| F-08-01 | 保存时自动生成版本快照 | 每次「保存」操作，自动将当前路线的完整快照（节点+连线+参数+视口）写入版本历史表 | P0 |
| F-08-02 | 查看版本历史列表 | 在编辑器内以时间线形式展示该路线的所有历史版本（版本号、创建时间、变更说明） | P0 |
| F-08-03 | 版本对比（差异视图） | 选中两个版本，以并排或差异模式展示节点和参数的变化 | P1 |

### 3.2 版本操作

| ID | 功能 | 描述 | 优先级 |
|----|------|------|--------|
| F-08-04 | 版本回滚 | 从历史版本列表中选择一个版本，将其恢复到编辑器（作为当前编辑版本） | P0 |
| F-08-05 | 变更说明 | 保存时弹出轻量输入框，让用户输入本次变更说明（必填，限 200 字） | P0 |
| F-08-06 | 版本号自动递增 | 每次保存时版本号自动递增（v0.1 → v0.2 → v0.3...），发布时跳主版本号（v0.x → v1.0） | P0 |

---

## 4. 业务规则

### 4.1 版本生成规则

- BR-V01: **每次保存**操作自动生成一条版本历史记录，版本号 +0.1（如 v0.1 → v0.2）
- BR-V02: **发布**操作将状态从 draft → published，版本号跳至 v{major+1}.0（如 v0.5 → v1.0）
- BR-V03: 已发布路线的「新建版本」将当前发布版本存档为历史，创建 v{major+1}.0 的新草稿

### 4.2 版本操作规则

- BR-V04: **回滚**操作不是删除历史，而是将选定版本的快照恢复到编辑器，自动创建新版本（v{x+1}）
- BR-V05: 只有 **draft** 状态可编辑和保存；published 状态必须先「新建版本」转为草稿
- BR-V06: 版本号格式为 `v{major}.{minor}`，major 从 0 开始，minor 从 1 开始
- BR-V07: 历史版本不可删除、不可编辑（只读）

### 4.3 保存触发规则

| 场景 | 行为 |
|------|------|
| 新建路线首次保存 | 创建 v0.1，写入历史 |
| 草稿路线保存（已有变更） | 创建 v0.2 → v0.3 ... |
| 保存时无变更（isDirty=false） | 不创建新版本，提示"无变更无需保存" |
| 发布操作 | 先保存当前快照（版本号 v{x}.{y}），再发布 → v{major+1}.0 |

---

## 5. 异常流程

| 场景 | 处理方式 |
|------|---------|
| 保存时数据库写入失败 | 提示"保存失败，请重试"，数据保留在内存中不丢失 |
| 查看历史时数据损坏 | 显示"该版本数据已损坏"标记，不影响其他版本查看 |
| 回滚时当前有未保存变更 | 提示"当前有未保存的变更，是否先保存再回滚？" |
| 版本历史超过 100 条 | 自动提示"版本历史已超过 100 条，建议归档早期版本" |

|------|------|

| 版本对比时选择同一版本 | 提示"请选择两个不同的版本" |
| 变更说明为空 | 保存按钮禁用，强制填写 |
| 回滚后立即保存 | 生成新版本，两个版本的快照内容相同（正常行为） |
| 版本号达到 v999.999 | 提示"版本号已达上限，建议发布新主版本" |

# TASK-005: 质检节点 PRD

> 版本: v1.0
> 角色: PM
> 日期: 2026-07-11
> 状态: 待审批

---

## 1. 概述

质检节点是工艺路线中的**特殊判断节点**，用于在流程中嵌入质量检查步骤。质检员在节点处记录检测结果（通过/不通过），路径根据结果分流——通过则继续下一工序，不通过则走返工或报废路径。

**一句话：在生产流程中嵌入「合格→继续，不合格→分流」的判断点。**

---

## 2. 用户角色

| 角色 | 说明 | 使用频率 |
|------|------|---------|
| **工艺工程师** | 在画布上放置质检节点，配置检测参数和标准 | 中频 |
| **质检员** | 在质检节点处记录检测结果（通过/不通过） | 高频（每批次） |
| **生产主管** | 查看质检节点的历史检测数据和合格率 | 低频 |

---

### 3.1 质检节点基础

---

## 4. 业务规则

### 4.1 节点规则

- BR-Q01: 质检节点**必须且有且只有两条出线**，分别对应「通过」和「不通过」
- BR-Q02: 质检节点有且只有一个入线（从上一工序接入）
- BR-Q03: 质检节点不需要关联 `process_library` 的工序，是内置特殊节点类型
- BR-Q04: 质检节点不可被删除（通过删除节点操作正常删除）

### 4.2 参数规则

- BR-Q05: 质检节点必须配置至少一个**检测项目**（如「工频耐压」、「外观检查」）
- BR-Q06: 每个检测项目可设置：检测名称、标准值、上限、下限、单位
- BR-Q07: 检测结果仅记录「通过/不通过」，不记录具体数值（简化设计）
- BR-Q08: 质检节点参数为空时节点标记为 invalid 状态（红色警告）

### 4.3 连接规则

- BR-Q09: 从「通过」端口引出的线标注为 ✅ 通过（绿色标签）
- BR-Q10: 从「不通过」端口引出的线标注为 ❌ 不通过（红色标签）
- BR-Q11: 两条出线可以分别连接到同一道后续工序（如都去修坯），也可以不同

---

## 5. 异常流程

| 场景 | 处理方式 |
|------|---------|

| 质检节点无检测项目 | 节点标记为红色 invalid，参数面板提示"请至少添加一个检测项目" |
