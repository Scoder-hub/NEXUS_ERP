# 线上测试与 UI 质量保障实施方案（Electron + Web）

> 目标：快速、稳定地发现并闭环解决 **布局错位、样式不一致、弹窗被遮挡、按钮点了没反应** 等“UI/交互类问题”。  
> 适用：Electron 桌面端 + Web（Chrome/Edge）双版本，配合《AI 协作规则树 v3.2》新增的「线上测试工程师」角色。

---

## 1. 为什么这些问题总是“测不出来”

这类问题通常无法通过“功能路径自测/业务 QA”稳定覆盖，根因通常是：

1. **缺少专门的验证出口**：UI/交互问题没有被制度化为发布门槛，靠“顺手看一眼”容易漏。
2. **缺少真实环境验证**：dev server 与发布产物（Electron 安装包/线上环境）存在差异（打包后样式、窗口尺寸、DPI、权限、资源路径等）。
3. **缺少调试取证能力**：没有人在线上环境用 DevTools/Electron 日志取证，开发者拿不到“可复现证据”。
4. **缺少自动化兜底**：截图回归与点击冒烟缺失，导致“回归后又坏了”很难提前发现。

---

## 2. 解决方案总览（四件事）

1. **制度化发布验证（Release Test）**：把 UI/交互问题纳入固定清单 + 固定文档产出。
2. **引入线上测试工程师角色**：上线/可访问环境验证 + 调试取证 + 回归闭环。
3. **补齐调试工具链**：Web 端用扩展，Electron 端注入 React DevTools + 规范化日志。
4. **加自动化兜底（Playwright）**：截图回归（视觉差异）+ 点击冒烟（可用性差异）。

> 备注：若系统新增了大量动效/复杂交互，发布前还应增加 **安全与性能基线**，见 `docs/安全与性能测试实施方案.md`。

---

## 3. 流程如何落地（结合 v3.2）

### 3.1 插入点（关键）
在 v3.2 的流程中：  
**DevOps 构建/部署 → 线上测试工程师验证（可多轮）→ 用户验收**

> 结论：**QA 通过 ≠ 发布通过**。必须经过“线上测试工程师”验证环节。

### 3.2 最小闭环（建议从下个版本立即执行）
1. DevOps 输出可访问环境/安装包（版本号、渠道、下载/访问方式）。
2. 线上测试工程师按固定清单执行验证，并产出 `docs/release-test-report.md`（或同名结构文档）。
3. 发现问题必须具备 **复现步骤 + 截图/录屏 + 日志摘要 + 严重度**。
4. 开发者按分工修复后，线上测试工程师回归验证并更新报告，直到通过或阻塞。

---

## 4. 线上测试工程师怎么测（固定清单）

建议把以下内容固化为每次发布的“冒烟清单”（Electron 与 Web 共用结构，按平台差异补充）：

### 4.1 布局与响应式
- 窗口最小化/最大化/恢复是否正常
- 常用分辨率/DPI（100%/125%/150%）下是否错位
- 列表页/详情页是否出现横向溢出、文字截断

### 4.2 弹窗/抽屉/下拉（最常漏）
- 是否被遮挡或裁剪（尤其是表格内下拉、侧栏内弹窗）
- 遮罩是否正确覆盖、是否阻止背景滚动
- ESC 是否可关闭、点击遮罩是否关闭（按产品约定）

### 4.3 可点击性（按钮点不动/无反馈）
- hover/disabled/loading 状态是否真实可用
- 点击后是否有反馈（toast/加载/路由变化/弹窗出现）
- 是否存在“点击穿透”或“被透明层盖住”

### 4.4 关键链路（每个版本至少覆盖）
- 每个核心模块至少 1 条主路径 + 1 条取消/返回路径
- 异常态：空数据、权限不足、网络失败/超时（按能力提供模拟）

## 5. 调试取证方法（让问题“可修”）

### 5.1 弹窗被遮挡/裁剪（高频根因与排查顺序）
常见根因：
1. **父容器 `overflow: hidden/auto`** 导致弹窗被裁剪
2. **z-index 失效**（父级创建 stacking context：`transform`/`filter`/`opacity<1`/`isolation`/`position+z-index` 等）
3. **Portal 使用不当**（弹层渲染在局部容器而非顶层挂载点）

排查顺序（建议线上测试工程师按此取证）：
1. DevTools 选中弹窗节点，确认其渲染位置（是否 Portal 到顶层）。
2. 查看父级链路是否有 `overflow` 裁剪。
3. 查看是否存在 stacking context，导致 z-index 再大也盖不过去。
4. 截图/录屏 + 记录关键 CSS（overflow/z-index/transform）。

### 5.2 按钮点不动/点了没反应（高频根因）
常见根因：
1. 有透明层/遮罩盖住按钮（`pointer-events`、全屏层、错误的定位）
2. 按钮处于 disabled/loading，但视觉上看不出来
3. 事件被阻断（stopPropagation）或绑定对象错误

取证方式：
1. 用 DevTools “选择元素”点击按钮，看实际点到的元素是谁（是否被遮罩盖住）。
2. 记录按钮的 disabled/loading 状态（截图 + HTML/属性）。
3. Console 记录错误日志/异常栈（必要时录屏）。

## 6. 工具与插件（快速见效清单）

> 原则：Web 端优先用扩展“快速发现”；Electron 端通过“注入 DevTools + 日志规范”实现同等能力。

### 6.1 Web（Chrome/Edge）扩展（建议必装）
1. **React Developer Tools**：定位组件树、props/state，排查“点了但没渲染/状态没变”。
2. **VisBug**：可视化检查间距/对齐/盒模型，快速发现错位。
3. **z-index / stacking context 调试扩展**：专治弹窗遮挡与层级异常。

可选：
- **Axe DevTools**：辅助发现可访问性/可点击性问题（聚焦、对比度等）。

### 6.2 IDE/编辑器（开发期防漏，建议启用的扩展/能力）

建议在开发环境中启用以下扩展：
- ESLint（尽早暴露潜在错误）
- Prettier（减少格式导致的回归/冲突）
- Error Lens（错误行内提示，降低漏看概率）
- Tailwind CSS IntelliSense（如使用 Tailwind，降低类名写错导致样式异常）

### 6.3 Electron 桌面端（建议做到与 Web 等价的调试能力）
强烈建议在 **开发模式** 注入 React DevTools（例如使用 `electron-devtools-installer`），让 Electron 的 DevTools 也能看到 React 面板。

> 注意：注入只建议在 dev 环境启用；生产包不建议默认启用。

## 7. 自动化兜底（Playwright：截图回归 + 点击冒烟）

### 7.1 为什么 Playwright 对你现在最有效
- **截图回归**：专抓“布局跑偏、弹窗被挡、样式丢失、字体/间距变化”
- **点击冒烟**：专抓“按钮不可点击、点击无反应、点击穿透、弹窗打不开”

### 7.2 建议的最小落地范围（先小后大）
第一期（建议 1 天内落地）：
- 5 个关键页面截图基线（登录、仪表板、核心列表页、核心详情页、设置页）
- 10 条关键点击冒烟（进入页面→点击按钮→断言弹窗出现/路由变化/出现 toast）

第二期（持续补充）：
- 每个模块补 1 条主路径 + 1 条取消路径
- 对高频弹层组件（Modal/Popover/Dropdown）增加“弹层展示态截图”

---

## 8. 实施步骤（落地顺序）

### Step 0：准备
- 统一“发布验证清单”结构与产出文档（`docs/release-test-report.md`）

### Step 1：Web 端（立即可做）
- 在 Chrome/Edge 安装：React Developer Tools、VisBug、z-index/stacking context 扩展

### Step 2：Electron 端（需要改项目）
- dev 环境注入 React DevTools（让 Electron DevTools 支持 React 面板）
- 建立日志取证规范（至少：console 错误、关键交互埋点/日志、崩溃信息位置）

### Step 3：Playwright（需要装依赖 + 建基线）
- 安装 Playwright 测试依赖
- 建立：截图基线 + 点击冒烟脚本
- 在 CI 或本地发布前跑一次（最少在发布前跑）

---

## 9. 成功标准（你应该看到的变化）

1. **弹窗遮挡/错位** 能在发布前通过截图 diff 或发布验证清单稳定发现
2. **按钮点不动/无反应** 能在点击冒烟中稳定复现（并附带取证）
3. 线上问题从“口述”变成“可复现证据”，修复效率显著提升
4. 回归后又坏的概率明显下降（自动化兜底 + 固定清单）
